# 이 파일, GitHub에 올려도 될까?

보안은 전문가만 하는 마지막 검사가 아니다. **올리기 전 10초 멈추는 습관**에서 시작한다.

## 30초 판정 퀴즈

| 파일·정보 | 올려도 될까? | 이유 |
| --- | --- | --- |
| `.env.example`의 빈 항목 | 가능 | 값이 없는 설정 예시 |
| 실제 `.env` | 금지 | 키·비밀번호가 포함될 수 있음 |
| 가상 학번 `20260000` | 조건부 가능 | 실제 학생과 겹치지 않게 명시 |
| 실제 학생증 사진 | 금지 | 신원·학번 등 개인정보 |
| 직접 만든 아이콘 | 가능 | 팀이 권리를 보유 |
| 검색해서 저장한 이미지 | 금지에 가까움 | 사용 허락과 출처가 불명확 |
| MIT 라이선스 라이브러리 | 조건부 가능 | 라이선스 고지·조건 확인 필요 |
| 회사 발표자료 일부 | 금지 | 공개 여부와 권한을 확인하지 않음 |

## S-T-O-P 체크

- **S — Secret**: 키·토큰·비밀번호가 있는가?
- **T — Traceable person**: 실제 사람을 식별할 수 있는가?
- **O — Ownership**: 우리가 사용·공개할 권리가 있는가?
- **P — Permission**: 학교·회사·교수·사용자의 허락을 받았는가?

하나라도 “모르겠다”면 Push하지 않는다.

## 절대 Commit하지 않는 것

- `.env`, 개인 인증서, SSH 키
- GitHub·클라우드·AI 서비스 토큰
- 실제 학번·전화번호·이메일·주소·호실
- 학생증·신분증·얼굴·차량번호가 식별되는 원본 사진
- 운영 DB와 관리자 계정
- 회사·연구실·외부기관의 비공개 문서
- 출처와 이용 조건을 모르는 코드·이미지·폰트·데이터

`.gitignore`에 있다고 안심하지 않는다. 이미 Stage했거나 이전 Commit에 포함되었는지 확인한다.

## 사고가 났을 때: 숨기지 말고 순서대로

1. 추가 Push와 공유를 멈춘다.
2. 팀장에게 파일·브랜치·노출 시간을 알린다.
3. 키나 토큰이면 즉시 폐기하고 재발급한다.
4. 개인정보라면 저장소 공개 범위와 접근 가능성을 확인한다.
5. 단순 파일 삭제로 끝내지 않는다. Git 이력에 남을 수 있다.
6. 필요한 경우 학교 담당부서·서비스 관리자·전문가에게 보고한다.
7. 원인과 재발 방지책을 기록하되 비밀값 자체는 기록하지 않는다.

실수보다 은폐와 늦은 보고가 더 큰 사고를 만든다.

## 테스트 데이터 만드는 법

나쁜 예:

```text
친구 이름, 실제 학번, 실제 기숙사 호실로 테스트
```

좋은 예:

```text
사용자: 테스트학생01
학번: TEST-0001
장소: 가상건물-A
전화번호: 저장하지 않음
이미지: 직접 촬영한 테스트 물건, 식별정보 없음
```

실제 데이터가 꼭 필요하다면 목적·항목·보관기간·접근자·삭제 방법을 먼저 정하고 담당자 승인을 받는다.

## 최소 수집 원칙

“언젠가 쓸 수도 있으니” 받지 않는다.

- 기능에 필요한 항목만 수집한다.
- 공개 정보와 소유 검증용 비공개 정보를 분리한다.
- 보관 이유가 끝나면 삭제한다.
- 관리자도 필요한 범위만 볼 수 있게 한다.
- 화면·로그·오류 메시지에 개인정보를 남기지 않는다.

## 오픈소스는 무료 이미지 창고가 아니다

공개된 코드라고 마음대로 복사할 수 있는 것은 아니다. 라이선스는 다른 사람이 무엇을 허용했는지 알려주는
조건표다.

새 의존성을 추가할 때 기록한다.

```text
이름 / 버전:
공식 저장소:
라이선스:
사용 목적:
수정 여부:
고지 또는 소스 공개 의무:
확인한 사람 / 날짜:
```

저장소에 LICENSE가 없으면 기본적으로 마음대로 복제·배포할 수 있다고 가정하지 않는다. 라이선스 선택이나
해석이 중요하면 산학협력단·변리사·법률 전문가에게 확인한다.

## 이미지·폰트·데이터 출처표

```markdown
| 자료 | 출처 URL | 제작자 | 라이선스/허가 | 사용 위치 | 확인일 |
| --- | --- | --- | --- | --- | --- |
```

“무료”, “출처: 구글”은 라이선스가 아니다. 검색 결과가 아니라 원본 제공 페이지를 기록한다.

## PR 보안 체크

- [ ] `.env`, 키, 토큰이 없다.
- [ ] 실제 개인정보와 원본 신분증 이미지가 없다.
- [ ] 로그와 스크린샷도 확인했다.
- [ ] 외부 코드·이미지·폰트·데이터의 출처와 조건을 확인했다.
- [ ] 새 라이브러리의 이름·버전·라이선스를 확인했다.
- [ ] 공개해도 되는 자료인지 소유자에게 확인했다.
