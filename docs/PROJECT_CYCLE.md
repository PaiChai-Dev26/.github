# Project Cycle

PaiChai Dev 26은 프로젝트를 다음 일곱 단계로 운영합니다.

## 1. Explore

### 확인할 내용

- 공모전의 목적, 평가 기준과 마감
- 실제 사용자가 겪는 문제
- 유사 서비스와 기존 해결 방법
- 필요한 데이터·장비·기술
- 팀이 사용할 수 있는 시간

### 산출물

- 공모전 후보 비교표
- 아이디어 메모
- 참고 자료
- 초기 질문 목록

## 2. Define

### 확인할 내용

- 해결하려는 문제를 한 문장으로 설명할 수 있는가?
- 주요 사용자는 누구인가?
- 반드시 필요한 기능은 무엇인가?
- 이번 프로젝트에서 만들지 않을 것은 무엇인가?
- 결과를 어떤 기준으로 확인할 것인가?

### 산출물

- 문제 정의
- 프로젝트 목표
- 최소 기능
- 제외 범위
- 성공 기준

## 3. Plan

### 확인할 내용

- 작업을 일주일 이하 단위로 나눌 수 있는가?
- 각 작업의 완료 기준이 명확한가?
- 담당자와 의존 작업이 정해졌는가?
- 예상 위험과 대안이 있는가?

### 산출물

- 일정표
- GitHub Issues
- 역할·작업표
- 위험 목록

## 4. Build

### 원칙

- 가장 위험한 기능을 먼저 시험합니다.
- 한 번에 많은 기능을 추가하지 않습니다.
- 다른 팀원이 실행할 수 있게 기록합니다.
- 막힌 문제를 숨기지 않습니다.

### 산출물

- 코드
- 기능별 문서
- 작업 기록
- 중간 화면 또는 실행 결과

## 5. Test

### 확인할 내용

- 핵심 사용 흐름이 처음부터 끝까지 동작하는가?
- 정상 입력뿐 아니라 잘못된 입력도 처리하는가?
- 팀원이 아닌 사람도 실행할 수 있는가?
- 제한사항과 미완성 기능이 기록돼 있는가?

### 산출물

- 테스트 사례
- 오류 목록
- 수정 기록
- 결과와 한계

## 6. Present

### 준비할 내용

- 문제와 필요성
- 해결 방법
- 핵심 기능
- 시연 흐름
- 검증 결과
- 한계와 다음 단계

### 산출물

- 발표 자료
- 시연 영상 또는 화면
- 제안서·보고서
- 예상 질문과 답변

## 7. Review

### 회고 질문

- 계획한 목표 중 무엇을 완료했는가?
- 가장 늦어진 작업은 무엇이며 왜 늦어졌는가?
- 팀장이 대신한 일이 있었는가?
- 다음 프로젝트에서 줄이거나 바꿀 것은 무엇인가?
- 재사용할 코드·문서·작업 방식은 무엇인가?

### 산출물

- 프로젝트 회고
- 팀원별 작업 정리
- 미완성 항목
- 다음 프로젝트 개선사항
