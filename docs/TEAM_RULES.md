# Team Rules

복잡한 규정보다 실제로 지킬 수 있는 기본 원칙을 사용합니다.

## Communication

- 일정이 어렵거나 구현이 막히면 마감 직전에 알리지 않습니다.
- 회의에 참여하기 어렵다면 가능한 시간을 미리 공유합니다.
- 모르는 내용을 아는 척하지 않습니다.
- 사람보다 문제와 결과물을 기준으로 의견을 나눕니다.

## Responsibility

- 이름만 올리는 참여는 하지 않습니다.
- 각자 맡은 코드 또는 문서 산출물을 직접 남깁니다.
- 다른 팀원의 작업을 설명 없이 대신 작성하지 않습니다.
- 도움이 필요한 경우 문제 상황과 시도한 내용을 함께 공유합니다.

## Scope

- 새로운 기능을 추가하기 전 기존 핵심 기능의 완료 여부를 확인합니다.
- 일정이 부족하면 야근보다 범위를 먼저 줄입니다.
- 팀장이 전체 구현을 대신하기 시작하면 즉시 작업을 다시 나눕니다.

## Records

- 중요한 결정은 Issue, README 또는 회의 기록에 남깁니다.
- 성공 결과뿐 아니라 실패 원인과 미완성 항목도 기록합니다.
- 프로젝트 종료 후 실행 방법과 회고를 정리합니다.

## Public Repository Safety

- 실명, 학번, 전화번호, 개인 이메일을 불필요하게 공개하지 않습니다.
- 비밀번호, API Key, 인증서와 `.env` 파일을 커밋하지 않습니다.
- 회사·연구실·외부 프로젝트의 비공개 자료를 올리지 않습니다.
- 외부 코드·이미지·데이터의 출처와 라이선스를 확인합니다.
- 교수님 또는 기관의 공식 참여는 승낙 후에만 표시합니다.
