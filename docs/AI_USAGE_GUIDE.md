# AI와 함께 개발하되, 운전대는 사람이 잡는다

AI는 빠른 페어 프로그래머가 될 수 있지만 제품 책임자도, 제출자도 아니다. 이 문서는 ChatGPT·Codex·
Copilot 등 생성형 AI를 **숨기지 않고 안전하게 활용하는 팀 기준**이다.

## 세 장면으로 시작하기

### 장면 1: 작동하니까 병합?

AI가 만든 로그인 코드를 실행했더니 된다. 하지만 작성자는 토큰이 어디에 저장되는지 설명하지 못한다.

**판정: 병합 금지.** 보안과 실패 조건을 설명하고 테스트할 수 있을 때까지 초안이다.

### 장면 2: 회의록 정리

개인정보를 제거한 회의 메모를 AI로 요약하고 팀원이 원문과 비교했다.

**판정: 가능.** 빠르고 위험이 낮으며 사람이 검증했다.

### 장면 3: 회사 문서를 붙여 넣기

회사에서 받은 비공개 자료를 “요약만” 부탁하려고 개인 AI 서비스에 입력한다.

**판정: 금지.** 요약 여부와 관계없이 외부 서비스로 자료를 전송한 것이다.

## 신호등 규칙

### 초록: 적극 활용

- 오류 메시지의 의미를 이해하기
- 테스트 아이디어와 반례 찾기
- 문서 목차·초안·맞춤법 점검
- 반복 코드의 초안을 만든 뒤 직접 검증하기
- 모르는 개념의 학습 순서 만들기
- 실제 정보가 아닌 가상 테스트 데이터 만들기

### 노랑: 리뷰 필수

- 인증·권한·결제·개인정보 코드
- 새로운 라이브러리나 모델 추천
- 특허·법률·의료·재무 관련 설명
- 성능·정확도 수치와 시장 규모
- 사용자에게 직접 노출되는 답변
- 대회 규정이나 논문 내용 요약

공식 출처와 실제 테스트로 다시 확인한다.

### 빨강: 입력·사용 금지

- API 키, 비밀번호, 토큰, `.env`
- 실제 학번·전화번호·주소·호실·학생증 사진
- 회사·연구실·교수님의 비공개 자료
- 허가받지 않은 데이터셋 전체
- 다른 사람의 과제나 코드를 대신 제출하기
- 출처를 꾸미거나 존재하지 않는 실험 결과 만들기

## AI 코드의 통과 조건: E-X-P-L-A-I-N

- **E**xecute: 직접 실행했다.
- **X**-ray: 입력·출력과 데이터 흐름을 설명한다.
- **P**rove: 테스트로 정상·실패 조건을 확인했다.
- **L**icense: 코드·모델·데이터의 출처와 라이선스를 확인했다.
- **A**dapt: 프로젝트 규칙과 기존 구조에 맞게 수정했다.
- **I**dentify: PR에 AI 사용 범위를 적었다.
- **N**o secret: 비밀정보와 개인정보를 입력하지 않았다.

하나라도 답하지 못하면 “완성 코드”가 아니라 학습용 초안이다.

## PR에 이렇게 적는다

```markdown
## AI 사용 기록

- 사용 도구:
- 사용한 목적:
- AI가 만든 범위:
- 내가 수정한 내용:
- 직접 확인한 테스트:
- 참고한 공식 문서:
- 남아 있는 불확실성:
```

AI를 사용했다는 사실은 감점표가 아니다. 검증하지 않았거나 숨기는 태도가 위험하다.

## 공모전·수업 제출 전

1. 해당 대회·수업의 AI 사용 규정을 읽는다.
2. 허용 범위가 불분명하면 주최 측이나 담당 교수에게 묻는다.
3. 프롬프트·수정·테스트 과정을 필요한 범위에서 기록한다.
4. 팀원 모두가 핵심 코드를 설명할 수 있게 리뷰한다.
5. “AI 기반 제품”과 “AI로 개발한 과정”을 구분해 발표한다.

## AI에게 질문하기 전 10초 점검

```text
이 내용이 공개 GitHub에 올라가도 괜찮은가?
실제 사람을 식별할 수 있는 정보가 있는가?
회사·학교·연구실의 비공개 자료인가?
답변이 틀렸을 때 사람이나 프로젝트가 크게 피해를 보는가?
내가 답변을 검증할 방법이 있는가?
```

하나라도 불안하면 원문을 넣지 말고 가상의 예시로 바꾸거나 팀장에게 먼저 묻는다.

## 팀의 AI 원칙 한 문장

> AI가 시간을 줄일 수는 있지만, 이해·검증·출처·결과에 대한 책임은 줄여주지 않는다.
