# 세 명이 다섯 분야를 맡는 법

> “세 명인데 화면·서버·AI·하드웨어·기획을 어떻게 다 하지?”  
> 답은 직업을 다섯 개 만드는 것이 아니라, **지금 필요한 일을 세 사람이 나눠 완주하는 것**이다.

## 1분 요약

- 모든 사람은 **주담당 1개 + 부담당 1개**를 가진다.
- 기획·문서·발표는 전원이 한다.
- AI와 하드웨어는 데이터·예산이 생긴 뒤 깊게 들어간다.
- 역할은 계급이 아니며 2주마다 바꿀 수 있다.
- 최종 발표에서는 각자 자신이 만든 것을 설명한다.

## 첫 번째 함정: 명함부터 만들기

```text
민수: 나는 AI 개발자!
지수: 나는 프론트엔드!
현우: 나는 PM!
```

멋있어 보이지만 아직 데이터도, 화면 설계도, 사용자 인터뷰도 없다면 AI 담당자는 할 일이 없고 PM은
혼자 문서만 쓰게 된다. 역할은 이름이 아니라 **이번 주 완료할 결과물**로 정한다.

## 다섯 분야의 실제 의미

| 분야 | 만드는 결과 | 처음 맡을 수 있는 일 |
| --- | --- | --- |
| 화면·웹 | 사용자가 보고 누르는 흐름 | 문구 수정, 폼 한 개, 오류 화면 |
| 서버·DB | 데이터 저장과 업무 규칙 | 조회 API, 입력 검증, 테스트 |
| AI·데이터 | 비교·분류·추천 근거 | 기준선 점수, 테스트 데이터, 오답 기록 |
| 하드웨어·IoT | 현실 장치와 상태 연결 | 가상 보관함, ESP32 조사, 상태표 |
| 기획·문서·발표 | 무엇을 왜 만들지 합의 | 인터뷰 기록, Issue, 시연 대본 |

## 추천 3인 구조

| 사람 | 주담당 | 부담당 | 전원 공통 |
| --- | --- | --- | --- |
| A | 제품·통합 | 서버·DB | 인터뷰·문서·리뷰·발표 |
| B | 화면·웹 | AI·데이터 | 인터뷰·문서·리뷰·발표 |
| C | 서버·DB | 하드웨어·IoT | 인터뷰·문서·리뷰·발표 |

팀원의 관심과 실력을 확인한 뒤 A·B·C에 실제 이름을 넣는다. 시작 배치는 영구 계약이 아니다.

## 역할 선택 미션

각자 아래 내용을 단톡방에 올린다.

```text
이름 / GitHub ID:
1순위 분야:
2순위 분야:
해보고 싶은 이유:
지금까지 해본 것:
이번 프로젝트에서 배우고 싶은 것:
일주일에 가능한 시간:
```

팀장은 세 답변을 보고 다음을 확인한다.

- 같은 분야에 세 명이 몰리면 한 명은 부담당으로 배치한다.
- 아무도 원하지 않는 필수 업무는 주 단위로 돌아가며 맡는다.
- 경험자에게 모든 어려운 일을 몰아주지 않는다.
- 가능한 시간을 능력이나 의지로 오해하지 않는다.

## 난이도 사다리

| 단계 | 예시 | 방식 |
| --- | --- | --- |
| L1 | 문서, 문구, HTML, 테스트 데이터 | 혼자 시도 후 리뷰 |
| L2 | 기존 패턴을 따른 API·화면·테스트 | 담당자 + 리뷰어 |
| L3 | 인증, 상태 전이, 배포, 장치 연동 | 두 명 이상 함께 |
| Spike | AI 모델·센서 등 불확실한 실험 | 시간 제한 후 결과 기록 |

처음 두 주는 모두 L1·L2를 경험한다. L3는 “잘하는 사람 벌칙”이 아니라 페어 작업으로 진행한다.

## 책임을 정하는 네 글자: D·R·C·I

- **D(Driver)**: 손을 움직여 결과물을 만드는 사람
- **R(Reviewer)**: 결과를 확인하는 사람
- **C(Consulted)**: 결정 전에 의견을 묻는 사람
- **I(Informed)**: 결과를 공유받는 사람

Issue마다 최소한 Driver와 Reviewer를 적는다.

```text
작업: 분실 신고 폼
Driver: @팀원A
Reviewer: @팀원B
Consulted: 운영 인터뷰 담당
완료 조건: 입력·오류·성공 화면과 테스트
```

## 2주마다 역할 건강검진

아래 질문 중 두 개 이상이 “예”면 역할을 조정한다.

- 한 사람만 항상 늦게까지 남는가?
- 팀장만 문서와 발표 내용을 알고 있는가?
- 본인 담당 코드인데 설명하지 못하는가?
- 재미있는 일과 반복 업무가 한쪽에 몰렸는가?
- 부담당이 실제로 파일이나 PR을 한 번도 보지 않았는가?

## 발표 전 최종 시험

세 명 모두 다음 질문에 30초 안에 답한다.

1. 우리가 해결하는 문제는 무엇인가?
2. 내가 직접 만든 것은 무엇인가?
3. 가장 어려웠던 결정과 근거는 무엇인가?
4. 지금 실패할 수 있는 부분은 무엇인가?
5. 다음 버전에서 무엇을 바꿀 것인가?

답하지 못하면 발표 연습 문제가 아니라 팀 내 지식 공유 문제다.
