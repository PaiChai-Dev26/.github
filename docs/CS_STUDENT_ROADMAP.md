# 컴퓨터공학과 대학생활·진로 로드맵

이 문서는 PaiChai Dev 26의 1학년 팀원이 수업, 프로젝트, 진로 준비를 연결하기 위한 가이드다. 특정 직업이나 복수전공을 정답처럼 권하지 않는다. **기초 실력 + 한 가지 전문성 + 실제 결과물 + 협업 기록**을 졸업 때까지 쌓는 것이 목표다.

> 배재대학교 공식 2025–2028 교육과정과 교과과정 페이지를 참고했지만 과목 개설·졸업 요건은 바뀔 수 있다. 수강신청 전 학사 공지, 학과 조교, 지도교수에게 반드시 확인한다.

## 1. 졸업할 때 남아야 할 것

- 자료구조·알고리즘·운영체제·네트워크·DB를 설명하고 적용하는 기초
- GitHub에서 읽을 수 있는 프로젝트 2~3개
- 본인이 맡은 문제, 결정, 코드, 테스트, 결과를 설명하는 능력
- 협업 경험: Issue, PR, 코드 리뷰, 일정·문서 관리
- 관심 직무 한 분야의 깊이
- 이력서 1장, 포트폴리오, 발표 또는 기술 글

자격증과 학점은 도움이 되지만 결과물을 대신하지 않는다. 반대로 프로젝트만 하고 전공 기초를 건너뛰면 면접과 장기 성장에서 막힌다.

## 2. 학년별 로드맵

### 1학년: 기초와 탐색

- C 문법, 컴퓨팅 사고, 이산수학, 웹 기초를 놓치지 않는다.
- Git, 터미널, 디버거, README 작성에 익숙해진다.
- 작은 프로그램을 끝까지 배포해 본다.
- 프론트·백엔드·데이터·하드웨어 역할을 짧게 순환한다.
- FindProof 목표: 로컬 실행, 작은 Issue 3개, PR 3개, 회고 1개.

### 2학년: 핵심 전공과 팀 개발

- 자료구조, 알고리즘, 컴퓨터구조, 데이터베이스, 소프트웨어공학을 연결한다.
- HTTP·API·SQL·테스트·Linux 기초를 익힌다.
- 관심 분야 두 개를 6~8주씩 경험한 뒤 주력 후보를 정한다.
- FindProof 목표: 하나의 수직 기능을 설계부터 테스트까지 책임진다.

### 3학년: 전문화와 현장 검증

- 운영체제, 네트워크, 보안, AI/데이터, 클라우드 중 진로에 필요한 깊이를 만든다.
- 캡스톤·공모전·연구실·인턴 중 최소 하나에서 실제 사용자를 만난다.
- 성능·보안·운영·비용을 포함한 기술 결정을 기록한다.
- FindProof 목표: 교내 실증 지표, 장애 대응, 포트폴리오용 사례 연구.

### 4학년: 증명과 전환

- 지원 직무별 이력서·포트폴리오·코딩 또는 직무 면접을 준비한다.
- 졸업작품을 “기능 목록”이 아니라 문제–역할–결정–결과로 정리한다.
- 취업, 대학원, 창업의 요구조건을 비교해 한 경로에 집중한다.
- 후배에게 인수인계 문서와 재현 가능한 실행 환경을 남긴다.

## 3. 전공선택 과목을 고르는 기준

과목명보다 **선수지식 → 수업에서 만들 능력 → 다음 과목·직무 연결**을 본다.

| 성향·목표 | 우선할 과목 묶음 | 함께 만들 결과물 |
| --- | --- | --- |
| 웹·앱 제품을 빨리 만들고 싶다 | 웹/모바일, DB, SW공학, 클라우드 | 배포된 서비스와 API |
| 서버·플랫폼이 재미있다 | 자료구조, OS, 네트워크, DB, 클라우드 | 부하·장애 테스트가 있는 백엔드 |
| AI·데이터가 재미있다 | 선형대수·확률, DB, ML, 정보검색 | 기준선과 평가 지표가 있는 모델 |
| 보안이 재미있다 | 네트워크, OS, 암호·정보보호, 보안 프로젝트 | 위협 모델과 방어 실습 |
| 임베디드·IoT가 재미있다 | 논리회로, 구조, 네트워크, 임베디드 | 센서–서버 연동 장치 |
| 게임·그래픽이 재미있다 | C/C++, 수학, 그래픽스, 게임엔진·AI | 플레이 가능한 빌드 |
| 기획·PM이 재미있다 | SW공학, DB, HCI/UX, 경영·통계 | PRD, 지표, 실험과 출시 기록 |
| 연구·대학원이 목표다 | 수학, 알고리즘, 관심 분야 심화, 연구방법 | 논문 재현과 연구 노트 |

쉬운 과목만 고르거나 이름이 최신인 과목만 모으지 않는다. 한 학기에 이론 심화 1~2개와 프로젝트 과목을 균형 있게 배치한다.

## 4. 진로 루트별 준비

### 프론트엔드

HTML/CSS/JavaScript, TypeScript, 브라우저·HTTP, 접근성, 테스트를 익힌다. 화면 개수보다 사용성, 상태 관리, 성능 개선을 설명할 수 있어야 한다.

### 백엔드·클라우드

한 언어를 깊게 익히고 API, SQL, 인증, 테스트, Linux, Docker, 배포·모니터링으로 확장한다. 트래픽 숫자를 과장하지 말고 부하 시험과 장애 대응 기록을 남긴다.

### AI·데이터

Python 도구 사용 전에 확률·통계·선형대수와 데이터 품질을 챙긴다. 데이터 출처, 기준선, 학습/검증 분리, 정확도 외 지표, 실패 사례를 기록한다.

### 보안

네트워크와 OS 기초를 먼저 다진다. 합법적인 실습 환경에서만 연습하고, 공격 도구 사용보다 위협 모델·로그·완화책을 설명한다.

### 임베디드·IoT

C/C++, 전자회로 기초, 통신 규격, 전원·고장 상태를 배운다. FindProof 보관함처럼 장치가 없어도 동작하는 소프트웨어 모의 어댑터부터 만든다.

### 게임·XR

수학, C#/C++, 자료구조, 그래픽스와 엔진 사용을 함께 익힌다. 완성된 짧은 게임과 팀 빌드·배포 경험이 큰 증거다.

### 기술기획·PM·창업

개발 기초를 버리지 말고 사용자 조사, PRD, 데이터 지표, 일정·위험 관리, 사업모델을 결합한다. “아이디어를 냈다”가 아니라 우선순위 결정과 검증 결과를 남긴다.

### 대학원·연구

관심 교수의 논문과 연구실 주제를 확인하고, 2~3학년부터 논문 읽기·재현·학부연구생 경험을 시도한다. 학위는 취업 회피가 아니라 더 깊은 연구가 필요한 목표인지 확인한다.

## 5. 복수전공·부전공 시너지

복수전공은 이름 두 개보다 **결합한 문제를 해결한 프로젝트**가 있어야 가치가 생긴다.

| 결합 분야 | 시너지 | 어울리는 진로·프로젝트 | 주의점 |
| --- | --- | --- | --- |
| 경영·창업 | 시장, 회계, 조직, 제품 판단 | PM, 기술사업개발, SaaS 창업 | 개발 깊이가 얕아지지 않게 한다 |
| 통계·수학 | 모델과 실험의 원리 | AI/ML, 데이터, 연구 | 선수 수학과 학습량이 크다 |
| 디자인·미디어 | UX, 시각 전달, 콘텐츠 | 프론트, UX 엔지니어, 게임/XR | 작품 과정과 사용자 검증을 남긴다 |
| 전자·전기 | 회로·센서·제어 | IoT, 로봇, 임베디드 | 실험 장비와 실습 시간이 필요하다 |
| 정보보안 | 안전한 시스템 설계 | 보안개발, 클라우드, 관제 | 도구보다 OS·네트워크 기초가 우선이다 |
| 바이오·헬스 | 도메인 데이터와 현장 문제 | 헬스테크, 바이오인포매틱스 | 개인정보·규제·검증 수준이 높다 |
| 심리·교육 | 행동·학습 이해 | EdTech, HCI, 추천·실험 | 사람 대상 조사 윤리를 배운다 |
| 행정·법·지식재산 | 제도, 공공조달, 권리화 | GovTech, R&BD, 기술사업화 | 법률 판단은 전문가와 협업한다 |

### 신청 전 네 가지 질문

1. 목표 직무에 정말 필요한가, 단순 호기심인가?
2. 졸업이 늦어지거나 핵심 전공을 놓칠 비용을 감당할 수 있는가?
3. 같은 효과를 부전공·마이크로디그리·교양·프로젝트로 얻을 수 있는가?
4. 두 분야를 결합한 결과물을 만들 계획이 있는가?

답이 불분명하면 한 학기 관련 과목을 먼저 들어보고 결정한다.

## 6. 대학생활 운영법

### 학기 시작

- 졸업 요건과 선수과목을 확인한다.
- 이번 학기 핵심 과목 2개와 결과물 1개를 정한다.
- 주당 수업·복습·팀 프로젝트 시간을 달력에 먼저 배치한다.

### 매주

- 수업 내용을 24시간 안에 짧게 복습한다.
- 막힌 문제와 해결 과정을 기록한다.
- GitHub에 작은 단위로 커밋하고 팀원 PR 하나를 읽는다.
- 건강, 수면, 인간관계를 프로젝트 희생 항목으로 두지 않는다.

### 방학

- 첫 1주는 회고와 휴식, 이후 하나의 목표에 집중한다.
- 강의 여러 개를 수집하기보다 작은 결과물 하나를 완성한다.
- 2학년 이후에는 인턴·연구실·오픈소스·공모전 중 목표와 맞는 경험을 찾는다.

## 7. 포트폴리오 기록법

프로젝트마다 다음을 남긴다.

1. 누구의 어떤 문제였는가?
2. 내 책임 범위와 실제 기여는 무엇인가?
3. 어떤 대안을 비교하고 왜 선택했는가?
4. 어떻게 테스트했고 결과는 숫자로 무엇인가?
5. 실패와 변경은 무엇이었는가?
6. 다시 한다면 무엇을 다르게 할 것인가?

커밋 수, 사용 기술 로고, 팀 전체 성과를 본인 실력처럼 쓰지 않는다.

## 8. 자격증·영어·코딩테스트

- 자격증: 목표 공고에서 요구하거나 기초를 정리하는 데 도움이 될 때 선택한다.
- 영어: 공식 문서와 오류 메시지를 읽는 습관부터 만든다.
- 코딩테스트: 1학년은 구현과 자료구조 기초, 이후 목표 기업 수준에 맞춘다.
- 학점: 기초 이해와 성실성의 신호다. 프로젝트 때문에 수업을 반복해서 포기하지 않는다.

## 9. FindProof로 연습하는 성장 경로

| 단계 | 맡을 수 있는 일 | 배우는 것 |
| --- | --- | --- |
| 입문 | 문서 오탈자, 실행 확인, 간단한 테스트 | GitHub 흐름과 코드 읽기 |
| 초급 | 입력 검증, 작은 화면, API 한 개 | 웹·DB·테스트 연결 |
| 중급 | 상태 전이, 인증, 매칭 평가 | 설계와 예외 처리 |
| 심화 | 배포, 모니터링, 개인정보, 보관함 연동 | 운영 가능한 시스템 |
| 리드 | PRD, 일정, 리뷰, 실증 지표 | 제품·팀·기술 의사결정 |

난이도는 사람의 서열이 아니다. 익숙해지면 다음 단계의 Issue를 선택한다.

## 10. 학기별 자기 점검
