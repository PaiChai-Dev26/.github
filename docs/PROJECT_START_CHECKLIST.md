# Project Start Checklist

새 프로젝트 또는 공모전을 시작하기 전에 아래 항목을 확인합니다.

## Problem

- [ ] 해결하려는 문제를 한 문장으로 설명할 수 있다.
- [ ] 주요 사용자가 누구인지 정해졌다.
- [ ] 팀원 모두가 문제와 목표를 이해한다.
- [ ] 유사한 해결 방법을 최소 한 번 조사했다.

## Scope

- [ ] 정해진 기간 안에 가능한 최소 기능이 있다.
- [ ] 이번 프로젝트에서 만들지 않을 범위를 정했다.
- [ ] 핵심 기능이 3개를 크게 넘지 않는다.
- [ ] 결과를 확인할 테스트 방법이 있다.

## Resources

- [ ] 필요한 데이터의 출처와 사용 가능 여부를 확인했다.
- [ ] 필요한 장비와 개발 환경을 확보할 수 있다.
- [ ] 외부 자료의 라이선스와 공개 범위를 확인했다.
- [ ] 회사·연구실·타 프로젝트 자료를 무단 사용하지 않는다.

## Team

- [ ] 각 팀원에게 직접 수행할 첫 작업이 있다.
- [ ] 역할이 아니라 구체적인 산출물로 작업을 나눴다.
- [ ] 개인별 가능한 시간을 확인했다.
- [ ] 일정이 어려울 때 공유하는 방법을 합의했다.

## Guidance

- [ ] 교수님 또는 전문가에게 확인할 질문이 정리됐다.
- [ ] 자문이 없어도 먼저 진행 가능한 작업을 구분했다.
- [ ] 외부 자문을 공식 참여나 보증처럼 표현하지 않는다.

## Decision

아래 중 하나로 결정합니다.

- `GO`: 현재 범위로 시작
- `REDUCE`: 기능 또는 기간 축소 후 시작
- `HOLD`: 데이터·장비·팀원 조건 확인 후 재검토
- `NO-GO`: 다른 프로젝트 선택
